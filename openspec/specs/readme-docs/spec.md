# readme-docs Specification

## Purpose
Keep the five README languages structurally in sync, with generated screenshots and project badges.
## Requirements
### Requirement: README in five languages
The repository SHALL provide the README in five languages:

| File | Language |
| --- | --- |
| `README.md` | Simplified Chinese |
| `README.en.md` | English |
| `README.zh-TW.md` | Traditional Chinese |
| `README.ja.md` | Japanese |
| `README.ko.md` | Korean |

Every file SHALL begin with the same language switcher linking all five, with the current language marked.

#### Scenario: Switching language
- **WHEN** a reader opens `README.ja.md`
- **THEN** the first line after the title block SHALL link to the other four README files
- **AND** mark Japanese as the current language

### Requirement: Shared README structure
All five README files SHALL contain the same top-level (`##`) sections in the same order:

1. Screenshot
2. What it solves
3. Features
4. Quick start
5. Usage
6. How it works
7. Release packages
8. FAQ
9. Development
10. License and acknowledgment

The Usage section SHALL document `--json`, the exit codes and `DEEPUNZIP_LANG`. A test SHALL fail when a README file is missing, lacks the switcher, or has a different number of `##` sections than `README.md`.

#### Scenario: Translation drifts
- **WHEN** a section is added to `README.md` but not to `README.ko.md`
- **THEN** the README structure test SHALL fail

### Requirement: Project badges
Each README SHALL show badges, linked to the repository, for the latest release, total downloads, downloads of the latest release, the release date, the CI status, GitHub stars, the license and the supported platforms.

#### Scenario: Download counts
- **WHEN** a reader opens any README
- **THEN** it SHALL show the total download count of all releases and of the latest release

### Requirement: Generated screenshots
The README files SHALL show a terminal screenshot produced by repository tooling, not by hand: `docs/images/terminal-<lang>.svg`, generated by `scripts/generate_screenshots.py` from the real terminal renderer and an event sequence recorded from a run on synthetic archives built by `scripts/make_demo_archives.py`. Rendering SHALL need no 7-Zip. `<lang>` is each output language: `zh`, `en`, `zh-TW`, `ja` and `ko`. Each README SHALL use the screenshot of its own language. Every image a README references SHALL exist.

#### Scenario: Regenerating screenshots
- **WHEN** a developer runs `poetry run python -m scripts.generate_screenshots`
- **THEN** the five SVG files SHALL be rewritten from the current renderer
- **AND** running it twice in a row SHALL produce identical files

#### Scenario: Demo archives contain no real content
- **WHEN** `scripts/make_demo_archives.py` builds the demo set
- **THEN** every archive SHALL contain only generated placeholder files
- **AND** the demo SHALL include a cloaked volume name and a volume set split across two containers
