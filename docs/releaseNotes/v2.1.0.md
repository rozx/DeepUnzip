# DeepUnzip v2.1.0

发布日期 / Release date：2026-11-22

2.1.0 让重复运行和中断后的再次运行更省心：输出文件夹里已有的相同文件不再另存副本，手动输入的密码一生效就保存，中断的运行留下的工作文件夹会自动清理。

Version 2.1.0 makes re-runs and runs after an interruption smoother: identical files already in the output are no longer saved again, a typed password is saved as soon as it works, and work folders left by interrupted runs are cleaned up automatically.

## 改进 / Improvements

- 输出文件夹里已有同名文件时，先比较大小和 MD5：内容相同就跳过，不再另存为 `a_1.txt` 这样的副本；内容不同仍像以前一样加编号保存。已有的编号副本也会逐一比较，中间有副本被删掉也一样，例如新文件与 `a_1.txt` 相同时，不会再生成 `a_2.txt`。同一次运行里几个压缩包解出的相同文件只保存一份。摘要会列出跳过了多少个相同文件。
- 中断的运行留下的 `temp.deepunzip-` 工作文件夹，会在下次对同一个文件夹的运行结束后自动清理：默认移到回收站，使用 `--permanent-delete` 时直接删除。如果里面还有没能放回原处的原始分卷，或者另一次运行还在使用它，或者这次运行也必须保留自己的工作文件夹，就保留它，并提示它的位置。

- When a file with the same name is already in the output folder, DeepUnzip compares size and MD5 first: identical content is skipped instead of being saved as a copy such as `a_1.txt`; different content still gets a numbered name as before. Every existing numbered copy is compared too, even past one that was deleted, so a new file identical to `a_1.txt` no longer becomes `a_2.txt`. Identical files from several archives in one run are saved once. The summary shows how many identical files were skipped.
- A `temp.deepunzip-` work folder left by an interrupted run is cleaned up when the next run of the same folder finishes: it goes to the recycle bin, or is deleted with `--permanent-delete`. It is kept, and its location shown, if it still holds an original volume that could not be moved back, if another run is still using it, or if the new run has to keep its own work folder too.

## 修复 / Bug fixes

- 运行中手动输入的密码以前要等整个运行结束才保存，中途按 Ctrl+C 或程序意外退出就会丢失。现在密码一解开文件就保存到程序旁边的 `passwords.txt`。

- A password typed during a run used to be saved only when the whole run finished, so Ctrl+C or a crash lost it. It is now saved to the `passwords.txt` next to the program as soon as it opens a file.

## 升级说明 / Upgrade notes

- 再次处理同一个文件夹时，`unzipped/` 里已有的相同文件会被跳过。以前运行留下的 `_1`、`_2` 副本不会被删除，需要时请手动清理。
- `--json` 的 `summary` 新增 `duplicates_skipped`（跳过的相同文件数）；`files` 对同一个输出文件只计一次。`schema_version` 仍是 `1`。
- 升级后的第一次运行结束时，会清理以前中断留下的 `temp.deepunzip-` 文件夹（默认移到回收站）。想保留里面的内容，请在运行前把它移走。
- “密码已保存”的提示现在在密码生效时显示，而不是在运行结束时。

- When the same folder is processed again, identical files already in `unzipped/` are skipped. `_1` and `_2` copies left by earlier runs are not removed; clean them up by hand if you like.
- The `--json` `summary` gains `duplicates_skipped` (the number of identical files skipped), and `files` counts each output file once. `schema_version` stays `1`.
- The first run after upgrading cleans up `temp.deepunzip-` folders left by earlier interrupted runs when it finishes (to the recycle bin by default). Move one away before running if you want to keep its contents.
- The "passwords saved" notice now appears when a password starts working, not at the end of the run.

## 已知问题与待验收 / Known issues and pending verification

- 仍不支持同时对同一个文件夹运行两次：两次运行共用改名记录，可能打乱对方的分卷拼合，但不会删除对方正在使用的工作文件夹。
- 相同文件按大小和 MD5 判断，理论上刻意构造的 MD5 碰撞文件会被当成相同文件而跳过。
- 中断后的清理和回收站行为只在 Linux 上用真实的 7-Zip 实测过（包括 Ctrl+C、强制结束和两次同时运行），Windows 和 macOS 尚未实机验证；Windows 上判断另一次运行是否仍在进行的代码只经过 CI 上的自动测试。
- 日文和韩文的输出文字与 README 译文（包括本次新增的内容）尚待母语者校对。
- macOS 和 Linux 版本只经过发布流程中的自动构建和冒烟测试，尚未在实机上手动验收。
- 程序没有代码签名，macOS 版也没有公证：Windows 可能显示 SmartScreen 提示，macOS 需要先执行 `xattr -d com.apple.quarantine ./deepunzip`。

- Running twice on the same folder at the same time is still not supported: the runs share the rename history and can disturb each other's multipart assembly, though neither removes a work folder the other is still using.
- Identical files are detected by size and MD5, so files deliberately crafted to share an MD5 hash would be treated as identical and skipped.
- The cleanup after an interruption and the recycle-bin behavior were tested with the real 7-Zip on Linux only (including Ctrl+C, a forced kill and two runs at once); they have not been checked on real Windows or macOS machines. The Windows check for whether another run is still going is covered only by the automated tests in CI.
- The Japanese and Korean output texts and README translations, including the text added in this release, still need a native-speaker review.
- The macOS and Linux builds are only covered by the automated build and smoke tests of the release workflow; they have not been checked by hand on real machines.
- The program is not code-signed and the macOS builds are not notarized: Windows may show a SmartScreen warning, and on macOS run `xattr -d com.apple.quarantine ./deepunzip` first.
